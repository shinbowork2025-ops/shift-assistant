# Shift Assistant

店舗PCのブラウザだけで動作する、社内システム登録前のシフト編成支援ツールです。正式な勤怠記録やシフト確定は社内システムで行います。

目標は、人が作成するものと同等以上のシフト案を効率よく作り、将来の正式採用時に会社固有の検査や連携を追加できることです。現状の出力は担当者が確認・承認するための候補案であり、ツールだけで正式登録まで完結するものではありません。

## 設計方針

- 静的なHTML・CSS・JavaScriptだけで動作
- 入力データはブラウザ内のIndexedDBに保存
- テスト環境用の固定資格情報による簡易ログイン
- シフトデータを外部サーバーへ送信しない
- JavaScript Object Notation（JSON）形式で全シフト表をバックアップ・復元
- Comma-Separated Values（CSV）またはExcel（`.xlsx`）でマスターを読込
- CSVでシフト案を出力
- 社内システム連携用のCSV・JSONを出力（形式は[docs/integration.md](docs/integration.md)で定義）
- ビルド処理や配信用の外部ライブラリを使わない

## 主な機能

- 複数のシフト表を作成・切替・複製・削除
- 従業員、雇用区分、所属、資格、勤務可能シフトの管理
- 月間シフト表のプルダウン入力、ペイント入力、希望休、セルロック
- 通常入力・シフト入力・セルロック・希望休をまとめた編集モード欄
- 月間表のコンパクト表示
- 従業員の複数選択による表示絞り込み
- 15分単位の1日チャート
- 休憩の自動配置、手動編集、自動再配置からの保護
- 合計人数、雇用区分、部門、資格者を含む必要人数設定
- 月間の勤務日数、実働時間、残業見込み、固定残業残の集計
- 月間ソルバーによる公休・勤務シフトの自動作成と改善
- 未入力数と問題種別を分けた月間の要確認一覧
- A4横の月間表と社内システム転記一覧
- ワークスペース別のUndo・Redo
- IndexedDBへの自動保存、別タブ競合検出、バックアップ経過表示

## 基本的な作業手順

1. テスト用の従業員IDとパスワードでログインする
2. ExcelまたはCSVから従業員とシフト区分を登録する
3. 従業員ごとに休み方、勤務可能シフト、優先シフトを設定する
4. 必要人数、必要部門、必要資格を設定する
5. 希望休や確定済みセルを入力してロックする
6. 月間ソルバーで案を作成する
7. 変更内容と不足・違反を確認して適用する
8. 1日チャートで休憩と配置人数を確認する
9. 月間の要確認一覧が「ツール内検証OK」になったことを確認する
10. 担当者が候補案とツールの未検査事項を確認・承認する
11. 印刷または転記一覧を使って社内システムへ登録する

## テスト環境用の簡易認証

起動時はログイン画面だけを表示し、認証に成功するまでIndexedDBの保存データを読み込みません。

- 従業員ID：`99999`
- パスワード：`99999`
- 同じタブの再読み込みでは`sessionStorage`の認証済み状態を維持
- 「ログアウト」で認証済み状態を消去してログイン画面へ戻る
- 初回パスワード変更、利用者登録、パスワード再設定は実装しない

資格情報は[auth-config.js](js/auth-config.js)、照合とセッション処理は[simple-auth.js](js/simple-auth.js)へ分離しています。正式採用時はこの固定資格情報を運用せず、社内の認証方式へ差し替えてください。

テスト用の資格情報を差し替える場合は、`userId`とパスワードの導出設定に加えて`profileId`も変更してください。既存タブに残る古い認証済みセッションを無効化できます。

この機能はテスト環境で画面を不用意に開かないための簡易認証です。静的JavaScript内で完結するため、端末を操作できる利用者に対する強固な本人確認、利用者別の権限分離、監査証跡は提供しません。

## 月間表の編集モード

月間表上部の「編集モード」から操作方法を切り替えます。

- **通常入力**：セルのプルダウンで1件ずつ入力
- **シフト入力**：選択したシフトをクリックまたはドラッグで連続入力
- **セルロック**：自動作成で変更しないセルをロックまたは解除
- **希望休**：希望休を登録または解除

`Esc`キーで通常入力へ戻れます。

## 月間表の表示設定

- **コンパクト表示**：セル幅、高さ、従業員情報を縮小して1画面の表示量を増やします
- **従業員を絞り込む**：複数の従業員を選んで月間表の行だけを表示します

絞り込みは画面表示だけに作用し、集計、印刷、月間ソルバーの対象は変更しません。

## 月間の要確認一覧

月間表の上部に、転記前に確認すべき状態を表示します。

- 空欄はエラー件数へ含めず、`未入力 ○セル`として別表示
- 空欄が残っている間は「ツール内検証OK」にはならない
- 同じカテゴリ・従業員・日付の問題は1項目へ集約
- 空欄以外の問題が1〜5項目なら初期状態で一覧を開く
- 6項目以上なら初期状態で一覧を折り畳む
- 一度開閉した状態は、セル編集による再描画後もシフト表・月ごとに維持
- 折り畳み中に新しいエラーが発生した場合は、自動で開かず件数表示だけを強調

集約された項目へ複数の詳細がある場合は、項目へマウスを重ねると内訳を確認できます。日付を持つ項目はクリックすると該当日の時間帯チャートを開きます。

## 月間ソルバー

月間ソルバーは、最初に公休と勤務シフトの初期案を作成し、その後に月全体を反復改善します。

評価順は次のとおりです。

1. 必要人数、雇用区分、部門、資格者の不足
2. 11時間未満の勤務間隔と連続勤務上限
3. 固定残業枠の超過
4. 休日数、土日勤務、遅番回数、シフト種別の偏り
5. 優先シフトと既存シフトの傾向

### 実行方法

- **高速**：短時間で案を確認するための設定
- **標準**：通常の月間作成で推奨する設定
- **精密**：最大3分間、異なる乱数条件で独立探索を繰り返し、その時間内で最も良い案を表示

精密実行でも全体最適解は保証しません。画面を固めないようWeb Workerで実行し、途中で中断した場合はその時点までの最良案を返します。

### 休日数の扱い

月間ソルバーは、初期案を作成した後の探索中に従業員ごとの休日数を増減しません。休日の位置は移動できますが、勤務日と休日の単純な置換は行いません。

初期案の時点で、ロックや既存休日のために目標休日数を満たせない場合は、案を適用できません。

### 案を適用できる条件

次をすべて満たした案だけ適用できます。

- 固定セルと使用可能シフト区分に矛盾がない
- 従業員ごとの休日数が目標と一致する
- 11時間未満の勤務間隔がない
- 連続勤務上限を超えていない
- 必要人数、雇用区分、部門、資格者の不足がない
- 探索後に対象セルが新しくロックされていない

条件を満たさない案は結果を確認できますが、「この案を適用」ボタンを表示しません。

## 休憩の自動配置と検証

休憩の法定最低時間は、休憩を差し引いた実働時間から判定します。

| 実働時間 | 必要休憩 |
| --- | ---: |
| 6時間以下 | 0分 |
| 6時間超〜8時間以下 | 45分以上 |
| 8時間超 | 60分以上 |

自動配置の基本設定は次のとおりです。

- 4時間以下の拘束：休憩なし
- 4時間超〜5時間の拘束：小休憩15分
- 5時間超〜8時間45分の拘束：昼休憩45分
- 8時間46分〜8時間59分の拘束：昼休憩60分
- 9時間以上の拘束：小休憩15分、昼休憩60分、小休憩15分

自動配置する休憩は、始業後60分以内と終業前60分以内を避けます。複数の休憩同士も60分以上空けます。

配置時刻は、これらの制約を守ったうえで、休憩を除いた実配置人数が手薄になる時間を減らすよう日全体で調整します。手動で保護した休憩は自動移動しません。

### 実働時間の計算

現行実装を正式な計算仕様とし、次の順で実働時間を決定します。

1. シフト区分に固定実働分が設定されている場合は、勤務時間や配置済み休憩にかかわらず固定実働分を使用
2. 固定実働分がなく、配置済み休憩を扱う転記一覧・連携用出力では、勤務時間から実際の休憩を差し引く
3. 固定実働分がなく、月間画面・通常のシフトCSV・月間印刷では、勤務時間からシフト長に応じた予定休憩を差し引く

そのため、固定実働分を設定したシフトでは休憩を手動変更しても実働時間は変わりません。固定実働分がないシフトでは、配置済み休憩が予定休憩と異なる場合、月間の見込値と転記一覧・連携用出力の値が異なることがあります。

## 必要人数の設定

1日チャートの「必要人数を設定」から、時間帯ごとに次を登録できます。

- 適用曜日：毎日、平日、土日
- 開始時刻、終了時刻
- 合計人数
- 社員、準社員、パート・アルバイト別の最小人数
- 必要部門と部門人数
- 必要資格と資格者人数

設定はブラウザ画面または配置条件CSVから登録できます。

## マスターCSV・Excel

「Excel見本」から、通常シフト、従業員例、休日区分を収録した`.xlsx`を取得できます。

取込時はファイル全体を先に検証し、データを変更する前に従業員・シフトの追加、更新、変更なし、読込不可の件数を表示します。

- エラーがなければ、確認後に全件をまとめて適用
- エラーがあれば、既定では取込を中止してデータを変更しない
- 利用者がプレビューで明示した場合だけ、正常行を部分適用
- エラー内容は画面で確認し、CSVでも保存可能
- ファイル内で同じ従業員コードまたはシフトコードが重複する場合はエラー
- 店舗での初期登録を省力化する暫定的な入力補助のため、ファイルへ形式版の入力は要求しない

基本形式：

```csv
種別,コード,名称,開始時刻,終了時刻,所属,表示順,略称,固定残業時間,シフト残業時間,実働分
従業員,E001,田中太郎,,,園芸,1,,20,,
シフト,01,,06:45,16:15,,,01,,0,480
```

- `従業員コード`：必須。社内システムとの照合キーのため、社員番号など全員で重複しない値を使用。全角・小文字は半角・大文字へ自動正規化し、同じコード（正規化後）の行は既存従業員の更新として扱う
- 従業員コード（社員ID）は変更されないことを前提とする。正式な人事マスター側で変更される可能性がある場合は、変更前後を結び付ける不変IDが別途必要
- シフトの`終了時刻`は`開始時刻`より後であること（日をまたぐシフトは登録不可）
- 取込でシフト時刻が変わった場合、勤務枠に収まらなくなった配置済み休憩は自動で再配置
- `雇用区分`：`社員`、`準社員`、`パート・アルバイト`
- `固定残業時間`：従業員の月間固定残業枠
- `シフト残業時間`：そのシフトを1回割り当てたときの残業見込み
- `実働分`：任意。シフト区分に固定する実働分を分単位で指定（例：`480`）。設定した場合は休憩からの計算より優先
- 固定残業時間・シフト残業時間は`20`、`1.5`、`01:30`の形式を利用可能
- 古い`.xls`、パスワード付きファイル、複雑な数式やマクロには未対応

マスターCSV・Excelの既存列は意味を変更しません。互換性のない入力項目が必要になった場合は既存列を読み替えず、別の見出しとして追加します。正式な人事マスター接続が安定稼働した後は、店舗向けの手動取込を廃止するか、管理者用の非常手段へ縮小します。

## 社内システム連携用の出力

「データ管理」の「社内システム連携用の出力」から、候補データのCSV（1行＝1従業員×1日）とJSON（マスター＋割当の全量）を保存できます。

- 従業員コードとシフトコードを照合キーとする
- 月間の要確認一覧が「ツール内検証OK」（未入力ゼロ・エラーゼロ）の場合のみ出力できる
- コードに欠落・重複・未正規化（全角や小文字）があると出力エラーになる
- JSONには検査プロファイル、実施した検査、未検査事項、担当者確認が必要なことを記録する
- CSVの各行にも形式版、候補状態、検査プロファイルとその版を記録する
- 出力成功はツールに実装された検査を通過したことだけを示し、就業規則全体への適合や承認済みであることは示さない
- フィールド定義とバージョン方針は[docs/integration.md](docs/integration.md)を参照

現時点で外部への自動送信は行いません。出力ファイルを社内システムのパイプラインへ接続する際の受け渡し形式として使用します。

## 保存とバックアップ

入力内容はIndexedDBへ自動保存します。

- 保存ごとにリビジョン番号を付け、別タブからの古い上書きを拒否
- 別タブの更新を検知した場合は再読み込み案内を表示
- ブラウザが対応している場合は永続ストレージを要求
- JSONバックアップの最終作成日時を表示
- 7日以上バックアップがない場合は注意表示
- バックアップには一意な識別子、作成日時、保存形式の版、シフト表数、対象月、従業員数、Secure Hash Algorithm 256-bit（SHA-256）による内容のハッシュ値を付与
- 保存形式の版4は版5へ段階的に移行し、旧単一シフト表形式も引き続き復元可能
- 未対応の古い版や、このツールより新しい版は推測して読み込まず復元を中止

ブラウザの閲覧データを削除すると保存内容も消えるため、定期的にJSONバックアップを作成してください。

バックアップファイルは、情報システム側の転送処理が内容を展開せずに管理情報を読める形式です。ツールはファイル出力までを担当し、共有フォルダ、端末管理ソフト、社内サーバーなどへの転送方法、保存期間、暗号化、アクセス権、復旧手順は正式利用時に情報システム部門が決定します。詳細は[バックアップ出力仕様](docs/backup-pipeline.md)を参照してください。

## 正式利用前の確認事項

本ツールは店舗でのシフト案作成と転記前確認を支援する試作版です。正式な勤務命令、勤怠記録、給与計算、社内システムへの自動登録を置き換えるものではありません。正式利用の判断前に、次を確認・決定する必要があります。

### データ保存と復旧

- ブラウザ内のIndexedDBは端末故障、ブラウザ初期化、利用者プロファイル削除で失われるため、バックアップを端末外へ転送する
- 転送先、保存期間、世代数、暗号化、アクセス権、転送失敗時の通知を情報システム部門が決定する
- 保存形式を変更する場合は1版ずつ移行処理を追加し、過去版の実データを用いた復元試験を行う
- 更新前後の復元試験、旧版への切戻し方法、許容できるデータ損失期間と復旧時間を決定する

### 権限・個人情報・監査

- 現在のログインはテスト環境用の固定1アカウントによる簡易認証であり、同じ資格情報を知る人を同一利用者として扱う
- 閲覧者・編集者・承認者・出力者・管理者の権限分離はない
- 従業員名、従業員コード、所属、資格、勤務予定を端末内およびバックアップへ保存することについて、社内の個人情報取扱基準を確認する
- 誰がいつ変更・承認・出力したかを示す永続的な監査記録はないため、必要なら社内基盤側で利用者認証と記録を追加する
- 編集者と承認者の分離、確定後の変更禁止、出力承認の要否を決定する

### マスター取込

- 現在のExcel・CSV取込は全件を事前検証し、エラーがある場合は既定で中止する。利用者がプレビューで明示した場合だけ正常行を部分適用する
- 現在のExcel・CSV取込は店舗での初期登録を省力化する暫定機能であり、現場に形式版の入力を要求しない。見出し名で形式を判定し、判定不能な形式や行ごとの必須値不足は取込前に拒否する
- 既存列の意味は変更せず、非互換な変更は別の見出しとして追加する。正式な人事マスター接続の安定稼働後に、店舗向け手動取込を廃止または管理者用へ縮小する
- 手作業のExcel・CSVは全従業員を含む保証がないため、ファイルから消えた従業員やシフト区分を自動削除しない
- 正式採用時は、対象店舗の全在籍者を含む人事マスターへアクセスできることを前提とする
- 正式な全件スナップショットであること、対象店舗、基準日時、社員ID、在籍状態または異動・退職日を確認できる場合に限り、マスターから消えた従業員を自動無効化する
- 従業員は物理削除せず無効化し、過去のシフト表には残して新しいシフト案の対象から除外する
- 従業員コード（社員ID）は変更されないことを前提とする。変更される運用の場合は不変IDと変更履歴の提供を人事マスター側の必須条件とする
- 実際の人事マスターと照合キー、必須列、重複、文字種、コード変更時の対応を確認する

### 勤務条件と計算仕様

- 「ツール内検証OK」は本ツールへ登録された必要人数、休憩、勤務間隔、連続勤務、残業見込みなどを通過した状態であり、就業規則全体への適合を保証しない
- 日・週・月単位の所定労働時間、契約時間、法定休日、年齢などに応じた勤務制限、月途中の入退社、個別の勤務可能時間は別途確認する
- 固定残業時間をシフト作成上の上限として扱うことが会社の運用と一致するか確認する
- シフト区分に固定実働分を設定した場合は固定値を優先し、未設定時だけ休憩を差し引く計算を正式仕様とする
- 必要人数の条件が重なる場合、同一人物が雇用区分・部門・資格の複数条件を同時に満たす計算でよいか確認する

### 社内システム連携

- 連携用出力はファイル形式を定義した段階であり、実際の社内システムへの取込、送信、登録結果の照合は未実装である
- 従業員コードとシフトコードの対応、店舗コード、出力者、承認状態、ツール版、再送時の重複処理、件数照合、エラー返却方法を接続先と決定する
- 連携用JSONの`formatVersion`とCSV各行の`format_version`はツールが自動付与する。既存フィールドの削除・意味変更時に版を上げる方針と接続先の対応版を合意する
- 出力ファイルを表計算ソフトで開く運用がある場合、数式として解釈される文字列への対策を確認する

### 配布・保守・試験

- GitHub Pagesの利用可否、公開範囲、会社管理の配布先、更新権限、障害時の連絡先、保守担当者を決定する
- 会社端末で使用するブラウザ、ブラウザ設定、保存容量、ダウンロード制限、ネットワーク制限を確認する
- 実店舗相当の従業員数・シフト区分数で性能を測定し、シフト担当者による操作試験と既存シフトとの比較を行う
- 現在のブラウザ自動試験は主要操作の一部だけであるため、バックアップ復元、マスター部分失敗、月間ソルバー適用、印刷、連携出力を含む一連の試験を追加する
- 開発用依存関係の版固定、リリース番号、変更履歴、配布前承認、問題発生時の切戻し手順を整備する
