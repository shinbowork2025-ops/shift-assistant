# 保存安全性・配置条件・月間確認

## 保存安全性

- 入力内容はブラウザのIndexedDBへ自動保存します。
- 保存ごとにリビジョン番号を付け、同じブラウザプロファイルの別タブで先に更新された場合は古いタブからの上書きを拒否します。
- 別タブの更新を検知すると、画面上部へ再読み込み案内を表示します。
- ブラウザが対応している場合は永続ストレージを要求し、結果を画面上部へ表示します。
- JSONバックアップの最終作成日時を表示し、7日以上経過または未作成の場合は注意表示します。

別タブ警告が出た場合は、古いタブでは編集を続けず、警告を押して再読み込みしてください。

## 希望休

希望休は通常のセルロックとは別のデータとして保存します。

1. 月間画面の「希望休」で休日区分を選びます。
2. 「希望休を塗る」を押し、対象セルをクリックまたはドラッグします。
3. 解除するときは「希望休だけ解除」を使います。

「希望休だけ解除」は希望休として登録したセルだけを解除し、通常の手動ロックは解除しません。

## 手動休憩の保護

休憩編集ダイアログの「自動再配置から保護」をオンにすると、当日全員の休憩再配置を実行しても、その従業員の手動休憩を維持します。

- 手動で休憩時刻を保存した場合は保護できます。
- シフト区分そのものを変更した場合は、以前の勤務時間に対する休憩を持ち越さないよう保護を解除し、新しいシフトへ再配置します。
- 未入力行、勤務時間外、重複、必要休憩不足がある場合は保存できません。

## 月間の要確認一覧

月間画面に「ツール内検証OK」または「要確認」を表示します。次を月全体で確認します。「ツール内検証OK」は以下の実装済み検査を通過したことを示すだけで、就業規則全体への適合や担当者の承認を示しません。

- 空欄・不明なシフト区分
- 必要人数、雇用区分、部門、資格者の不足
- 休憩の未配置・不足・重複・勤務時間外
- 11時間未満の勤務間隔
- 連続勤務上限
- 固定残業枠の超過
- 希望休データとセル内容の不一致
- 手動休憩保護データの不整合
- 前月末・翌月初の登録状況

前月または翌月の同じ従業員のシフトが登録されている場合は、月境界をまたぐ勤務間隔と連続勤務も判定します。未登録の場合は情報メッセージを表示します。

## 部門・資格を含む配置条件

1日チャートの「必要人数を設定」から、次の条件をブラウザ上で設定できます。

- 適用曜日：毎日・平日・土日
- 開始・終了時刻
- 合計人数
- 社員・準社員・パート／アルバイト別人数
- 必要部門と部門人数
- 必要資格と資格者人数
- 従業員ごとの保有資格

同じ時間帯へ複数の条件を登録できます。合計不足と属性不足は単純加算せず、そのスロットで実際に追加が必要な最大人数として評価します。

## 配置条件CSV

設定ダイアログから次を利用できます。

- `配置条件CSVを読込`
- `現在値をCSV保存`
- `CSV見本`

CSVはUTF-8で、1行目に次の見出しを使用します。

```csv
種別,従業員コード,氏名,保有資格,曜日,開始,終了,合計,社員,準社員,パート・アルバイト,必要部門,部門人数,必要資格,資格者人数
```

### 従業員資格行

`種別`を`従業員資格`にします。従業員コードを優先して照合し、コードが空の場合は氏名で照合します。複数資格はセミコロン、読点、カンマのいずれかで区切ります。

```csv
従業員資格,E001,田中太郎,危険物取扱者;農薬アドバイザー,,,,,,,,,,,
```

### 必要人数行

`種別`を`必要人数`にします。曜日は`毎日`、`平日`、`土日`を指定します。

```csv
必要人数,,,,平日,09:00,17:00,4,1,0,0,園芸,1,農薬アドバイザー,1
```

部門人数を1以上にする場合は必要部門、資格者人数を1以上にする場合は必要資格を必ず入力してください。

## 自動テスト

Pull Requestでは次を自動実行します。

- 全JavaScriptファイルの構文確認
- Node.jsユニットテスト
- Playwright Chromiumによる起動・保存安全表示・月間確認・配置条件ダイアログの操作テスト

失敗時のユニットテストログとブラウザテストログは、GitHub Actionsの成果物へ7日間保存します。
